# AttendX Local Run Blockers

**Review date:** 2026-11-10
**Scope:** Source review and isolated validation only. No `.env`, credentials, database, PostgreSQL service, SMTP, or production service was accessed.

## Summary

The repository contains substantial frontend and backend implementation, but the complete registration-to-attendance workflow is **BLOCKED** at the unverified database/schema boundary and at account activation/attendance-write boundaries. Synthetic SQLite tests and a temporary frontend smoke server do not verify the configured PostgreSQL database or a real end-to-end workflow.

## Verified local validation

- Frontend serial tests: **111 passed** across 23 files; an initial sandbox run returned Windows `spawn EPERM`, then the serial retry passed.
- Safe Vite production validation build: passed with dotenv/config files disabled, inherited `VITE_*` variables cleared, a reserved `.invalid` API URL, and `write:false`.
- Temporary Vite startup smoke test: `http://127.0.0.1:5173/` returned HTTP 200, then the temporary server was closed. This does not prove API connectivity or leave a local service running.
- Focused backend registration and tenant authorization tests: **32 passed** using explicit synthetic in-memory SQLite.
- Full backend isolated suite: **258 total, 223 passed, 23 failed, 12 errored**. The assertion failures are legacy feature-success expectations against the unchanged default-deny 503 gate; 10 setup errors duplicate ORM-created SQLite tables; two reconciliation CLI tests hit Windows temp-file permission failures.
- Python AST and documentation whitespace checks passed. PostgreSQL, SMTP, actual configured database persistence, browser E2E, and production behavior were not tested.

The test details and current migration audit are in `TEST_RESULTS.md`, `ATTENDX_DATABASE_MIGRATION_PRECHECK.md`, and `ATTENDX_LOCAL_EXECUTION_ACCEPTANCE_REPORT.md`.
